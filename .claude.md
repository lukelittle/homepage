- **Default Region:** us-east-1
- **Environment:** Production

## Terraform State Backend

Remote state is managed using the shared Terraform state backend infrastructure.

### S3 State Bucket

- **Bucket Name:** `168737286209-us-east-1-tf-state`
- **Purpose:** Store Terraform state files for all projects in this AWS account
- **Features:**
  - Versioning: Enabled
  - Encryption: AES256 (server-side)
  - Public Access: Blocked
  - Lifecycle Policy: Old versions deleted after 90 days

### DynamoDB Lock Table

- **Table Name:** `tf-lock`
- **Purpose:** Prevent concurrent state modifications
- **Billing Mode:** Pay-per-request
- **Hash Key:** LockID (String)

## Homepage Terraform State Configuration

This project uses the following state configuration:

```hcl
terraform {
  backend "s3" {
    bucket         = "168737286209-us-east-1-tf-state"
    key            = "homepage/terraform.tfstate"
    region         = "us-east-1"
    dynamodb_table = "terraform-state-lock"
    encrypt        = true
  }
}
```

## Using This Backend in Other Projects

When creating new Terraform projects that need to use this state backend, add the following configuration:

```hcl
terraform {
  backend "s3" {
    bucket         = "168737286209-us-east-1-tf-state"
    key            = "PROJECT_NAME/terraform.tfstate"
    region         = "us-east-1"
    dynamodb_table = "terraform-state-lock"
    encrypt        = true
  }
}
```

**Important:** Replace `PROJECT_NAME` with a unique path for each project.

### Recommended State File Organization

Organize state files by environment and project:

- `production/vpc/terraform.tfstate` - Production VPC
- `production/eks/terraform.tfstate` - Production EKS cluster
- `staging/vpc/terraform.tfstate` - Staging VPC
- `dev/app/terraform.tfstate` - Development application
- `global/iam/terraform.tfstate` - Global IAM resources

## Deployment Workflow

### Initial Setup (One-time)

1. Ensure AWS credentials are configured:
   ```bash
   aws configure
   # Or use environment variables:
   # export AWS_ACCESS_KEY_ID=...
   # export AWS_SECRET_ACCESS_KEY=...
   ```

2. Initialize and deploy the state backend:
   ```bash
   cd /path/to/tf-aws-state
   cp terraform.tfvars.example terraform.tfvars
   terraform init
   terraform plan
   terraform apply
   ```

### Using the Backend in New Projects

1. Add backend configuration to your project's Terraform code
2. Initialize Terraform (will prompt to configure backend):
   ```bash
   terraform init
   ```
3. Deploy your infrastructure:
   ```bash
   terraform plan
   terraform apply
   ```

### Migrating Existing Projects

If you have existing local state files:

1. Add the backend configuration block
2. Run migration:
   ```bash
   terraform init -migrate-state
   ```
3. Confirm migration when prompted
4. Optional: Delete local state files after verifying migration

- S3 bucket has encryption at rest enabled
- Public access is completely blocked
- State locking prevents race conditions
- Versioning allows recovery from accidental changes

## Troubleshooting

### Lock Stuck/Not Released

If a Terraform operation is interrupted, the lock may remain:

```bash
# Force unlock (use with caution!)
terraform force-unlock LOCK_ID
```

### State File Corruption

If state becomes corrupted, restore from S3 version history:

```bash
# List versions
aws s3api list-object-versions --bucket 168737286209-us-east-1-tf-state --prefix PROJECT_NAME/

# Download specific version
aws s3api get-object --bucket 168737286209-us-east-1-tf-state \
  --key PROJECT_NAME/terraform.tfstate \
  --version-id VERSION_ID \
  terraform.tfstate.backup
```
